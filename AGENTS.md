# CyberArch-Shell → Ubuntu Hyprland Port

Ziel: https://github.com/ARCANGEL0/CyberArch-Shell (Arch-only Hyprland-Rice) auf Ubuntu 26.04 + Hyprland
lauffähig machen. Getestet wird in einer QEMU/KVM-VM, Schritt für Schritt alle Widgets.

## Umgebung

- Host: Ubuntu 26.04 (resolute), Hyprland 0.57 aus PPA `ppa:cppiber/hyprland`, 16 Kerne, 59 GB RAM, KVM ok
- QEMU 10.2 mit `virtio-vga-gl` (GPU-Beschleunigung für Hyprland in der VM)
- Keine ISO-Tools auf dem Host → cloud-init NoCloud über lokalen HTTP-Server (`10.0.2.2`) per SMBIOS-Seriennummer
- VM-Dateien: `vm/` (base.img = Ubuntu 26.04 Cloud-Image, `disk.qcow2` = Entwicklungs-VM, `clean.qcow2` = End-to-End-Test, `seed/`)
- Start: `vm/start-vm.sh` (Fenster) · zweite VM: `DISK=clean.qcow2 SSH_PORT=2223 VNC=2 vm/start-vm.sh headless` (`vm/ssh_config_clean`, Host `cvm2`)
- Repo-Klon zum Analysieren: Scratchpad `src/CyberArch-Shell` (3.9 GB, v. a. Video-Wallpapers)

## Analyse des Repos

- HUD: **AGS v3** (`ags run --gtk 3 core.ts`) mit **GTK3 + Astal** (astal-io, astal3, AstalNotifd, AstalWp, AstalMpris), gnim
- Hyprland-Config ist **Lua** (`~/.config/hypr/hyprland.lua` → `require("theme")`, `require("user")`), braucht Hyprland ≥ 0.56
- Theme liegt unter `~/.config/hypr/themes/cyberpunk` (Symlink auf Klon)
- Lockscreen: **Quickshell** (`qs`) + PAM-Datei `/etc/pam.d/qs-lock` (auf Arch `system-auth`, Ubuntu: `common-auth` usw.)
- Login: SDDM-Theme „netwatch“
- Wallpaper: `mpvpaper` / `awww` (Videos)
- Terminals: Rio (cargo, optional), cool-retro-term (AppImage), kitty
- Arch-spezifisch: pacman/yay/paru, pacman-Hook (Street-Cred-Animation), `scripts/aur`, `scripts/pkg-notify`, `cmodal.ts` (System-Upgrade-Modal)

## Architektur der Portierung (`ubuntu/`)

| Datei | Zweck |
| --- | --- |
| `make-installer.sh` | erzeugt `../cyberarch-ubuntu-install.sh` (Ein-Datei-Installer mit Optionen `--interactive`, `--no-fish`, `--no-upgrade`, `--keep-greeter`, `--dir`, `--ref`) |
| `install-ubuntu.sh` | Einstieg: klont Upstream (Commit 1b3c616 = v2.3.26), kopiert Schicht nach `<repo>/ubuntu/`, wendet Patch an, startet `install.sh` |
| `compat.sh` | Von `install.sh` gesourct: Funktionen `pacman`, `sudo` (nur `sudo pacman`/pacman-Hook), `pac_install`, `aur_install`, `pkg_has` → apt + Builds; Paket-Mapping Arch→Ubuntu; `ubu_prepare` (PPA, packages.txt, Builds, PAM qs-lock mit common-*) |
| `build-deps.sh` | Quellcode-Builds: astal, astal-gjs, ags, quickshell, mpvpaper, awww, nerdfonts |
| `packages.txt` | apt-Pakete (Laufzeit + Build) |
| `kde-colors.sh` | Dunkles KDE-Farbschema „CyberArchDaemon“ für Dolphin & Co. (lesbare Schrift unter Kvantum) |
| `apt-pkg-notify` | apt-Hook (`DPkg::Pre-Install-Pkgs`/`Post-Invoke`) statt pacman-Hook → `scripts/pkg-notify` |
| `upstream.patch` | Änderungen am Upstream: compat-Hook in install.sh, Polkit-Agent (hyprpolkitagent), `scripts/aur` (apt), `scripts/pkg-notify` (dpkg), `cmodal.ts` (Paketanzahl via dpkg); SUPER+Enter → kitty im user.lua-Template; Bugfixes: autogenerierte hyprland.lua ersetzen, Rio-Shader-Check, SDDM-Background.qml |

Offene Punkte / Risiken:
- `updater.sh` (Upstream) stasht lokale Änderungen → nach einem Update muss `install-ubuntu.sh` den Patch erneut anwenden.
- CyberSpace-Client braucht WPE WebKit (nicht in Ubuntu) → bleibt optional/aus.
